# 2026-11-04：原生 SSH 保活使用系统 TCP 检测，移除辅助 SSH 通道

状态：源码实现待定向构建、真实连接与主会话独立验收；本文不代表用户中断事件已复现。

## 问题与证据

生产原生 SSH 将主机保活间隔和倍数映射为一个辅助 session-channel open 的连续等待截止时间，打开成功后还需在普通 operationTimeout（当前10秒）内 close/free。它不执行命令，但依赖服务器允许额外通道和正常辅助清理。辅助步骤的错误、超时会结束主 shell，与2026-11-04用户“保活不得依赖额外 shell/exec 频道、不能因辅助能力限制判断主连接已断”的要求不符。

旧实现对固定 libssh2 的确切 MaxSessions/open-failure 回复已有“仍活着”的分类，历史正例和黑洞证据均保留。不能把用户截图的 connectionLost 直接归因为 MaxSessions、网络或服务器；该截图没有实际 operation/code/发生时长。普通 receive 的0.25秒等待只返回 wouldBlock，本身不是会话闲置寿命。每个标签具有独立 socket、取消令牌和队列，源码调查未证实跨标签或 SFTP 共享计时器误断。

固定 libssh2 1.11.1 的 public keepalive_send 会在 transport EAGAIN 时仍更新时间并返回0，未公开匹配回复/遗漏计数。底层续写要求相同原始参数，直接重调可能先被间隔短路。因此不以该返回值构造 SSH 响应证据，也不使用 raw recv 字节冒充经验证的 SSH 回复，不修改上游源码或自写 SSH 消息。

## 决定

用 macOS 已有 TCP 保活替代生产辅助通道逻辑，不新增依赖、协议实现或后台认证：

- 主机间隔0关闭；正值按原数据库整数精确映射，空闲首次探测和后续重试均使用该秒数，失败探测次数使用原 count（1–10）。不迁移或重写用户数据。
- 对本连接独占的 socket 设置 SO_KEEPALIVE、TCP_KEEPALIVE、TCP_KEEPINTVL、TCP_KEEPCNT，随后逐项 getsockopt 验证。返回不可变实际值供诊断；系统拒绝或读回不符则明确失败，不静默关闭检测。
- 不再开启额外 SSH channel，无应用层 idle/probe/辅助清理定时器。内核负责空闲 TCP 检测，不需要终端输出或输入。正常 quiet receive 仍返回 wouldBlock。
- 原 read/window-adjust、write、resize/EOF 单操作的有界进展、稳定 EAGAIN 参数、输入背压、取消与 native 资源排空不放宽。真正 EOF、传输错误或单次协议操作失败继续可见，保留历史并只允许人工重连。
- 脱敏失败详情增加已连接的单调时长（整秒、最大一年）、已应用 TCP 参数、固定的本地关闭发起路径。它们不推断服务器具体原因，不包含端点、凭据或终端内容。已有错误码与认证阶段保留，补齐真实固定操作名白名单。

## 准确能力边界

TCP 保活检测对端 TCP 栈或网络路径失联，不保证 SSH daemon/远端应用健康。若中继仍 ACK TCP 却丢弃应用字节，不能拿它验证本策略能发现 SSH 应用层黑洞。保活也不保证远端任务在断线后继续，不覆盖服务器 TMOUT/账户退出政策。实际失联时间受内核调度和已有在途数据重传影响，不能继续展示“interval×count 就是 SSH 回复截止时间”或精确秒数 SLA。

本轮使用既有隔离服务做有限两个标签（一空闲、一持续输出）超过原默认120秒故障窗和多个30秒周期，之后输入明确测试命令；同时做 SFTP超过60秒/切页/列目录/上传/显式关闭与 SSH 隔离。真正断开验证可使用仅本轮拥有连接的 FIN/RST；这不能称为 TCP 层黑洞通过。没有新的环境、路由或防火墙授权时不制造额外环境。
