## 四项结果与实际原因

1. **SFTP 闲置断开：已修复。** 原服务使用者只有任务和操作，没有独立的用户连接持有者，因此即使界面仍保持连接也会进入60秒闲置回收。现在用户持有独立会话租约，切页、观察者变化不会撤销；无人持有的后台服务仍回收。30秒只读健康检查通过现有串行协议操作执行，真实终态按连接归属释放。
2. **终端悬浮说明：已删除。** 仅移除终端区域的 `toolTip` 赋值，其余实现不变。实际单行粘贴、shell 执行、双击选词及终端指针处无旧灰色提示已检查；没有借此重写选择、TUI 或输入法行为。
3. **普通上传被能力证据阻挡：已修复。** 原入口、引擎及底层提交均要求手工取得非覆盖提交证据。现在正常上传在实际目标父目录内，以本任务独占临时对象自动检查安全能力，证据绑定具体连接及父目录；不跨连接或目录错误复用。保留同名选择、独立路径风险及明确覆盖确认。无法证明安全提交或没有权限时准确拒绝，没有默认放行覆盖式 rename 或假称通用替代保证。
4. **SSH 使用一段时间后中断：部分解决，用户原事件待复现。** 已确认旧保活依赖额外 SSH 会话频道，辅助操作或清理失败存在牵连主会话的路径；旧探测没有执行用户 shell 命令。现移除该路径，按连接使用内核 TCP 保活并读取实际参数，保留真实 I/O 故障检测及各标签独立归属。新增脱敏阶段、原码、时长、关闭来源与实际保活值。用户暂时没有原事件详情，不能把此风险写成该服务器那次中断的已证根因；TCP 仍确认但 SSH 应用卡死的黑洞场景未证实。
