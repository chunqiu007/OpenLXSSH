## 3. 应做的工作区结构

```text
顶部统一标签栏：[保险箱 Vault] [SFTP] [SSH-A ×] [SSH-B ×] [+]
内容区：只显示当前工作页，充分使用标签栏下方的窗口面积
```

### 3.1 固定标签和会话标签

- Vault 永远第一、SFTP 永远第二；两者不可关闭，不显示关闭按钮。
- 后续标签是一条实际 SSH 会话，名称来自主机名称；允许关闭、切换及对同一主机显式新建独立会话。`+` 打开清晰的主机选择／新建连接入口。
- 多标签超出宽度时，提供可用的横向滚动／左右导航；保留合理最小宽度，不能把标签和关闭按钮挤没。固定两个标签应可直接访问。
- 切换 Vault、SFTP、任意 SSH 标签只换呈现，不重建 PTY、终端、认证请求或文件服务，不断开连接，不丢搜索／历史／传输状态。
- 固定标签不可被 Cmd+W 当作普通会话删除；窗口退出仍服从已有传输保护和资源回收流程。

### 3.2 Vault / 保险箱

- 本项目“保险箱”是本地配置工作区，仍用现有数据库、私钥存储和 Keychain；不新增云账号、同步服务或自研加密容器。
- Vault 内左侧导航安排：主机、密钥与凭据、已知主机，以及设置／传输任务等已有管理入口。收藏、文件夹、搜索与现有管理操作不能丢。
- 主机页中心展示清楚的主机列表或卡片；右侧为可收起的详情／编辑面板，参考图六。密钥管理为 Vault 的子页，参考图三。
- 各页统一字体、间距、行高、圆角和选中态；显示 OpenLXSSH 名称，用自身或系统图标。不要做成混杂原生大按钮的调试面板。
- 不为模仿截图摆放不可用的 Port Forwarding、Snippets、Certificates、FIDO2、Serial、Mosh、AI 或云同步按钮。按完整规格将这些能力逐项列入差异表，明确本轮实现、适配或范围外的理由，不能无声遗漏。正常主机/密钥/终端/SFTP使用所需的新UI和状态模型按完整规格实现，不以“旧代码没有”自行缩小任务。

### 3.3 SSH 页面

- 选中 SSH 标签后，顶部标签栏下方基本整页均为终端；不再在终端上方长期放主机列表、详情卡、文件面板和大段说明。
- 搜索用 Cmd+F 打开的紧凑搜索条；连接状态／重连等可放在小工具栏、标签菜单或就地状态页，不挤占主要终端高度。

## 5. 主机创建、编辑与连接

- 参考图六：地址、常规信息、SSH端口、凭据分组，基本字段紧凑整齐；保活等高级选项折叠。
- 界面只显示两种主认证方式：**密码**、**SSH密钥**。用户名是两种方式的共同字段。
- 密码方式输入密码，使用普通“记住密码”开关；密钥方式选择已有密钥或进入导入／生成入口，支持有口令／无口令密钥，记住私钥口令仍是明确选择。
- 提供明确的“保存”和“保存并连接／连接”。不必照搬 Termius 的自动保存；若采用自动保存，须有确定的验证、取消及秘密处理语义，不能丢数据。
- **已在编辑器填入密码并点连接时，不记住也必须能将它以内存中本次授权交给这次认证；不能静默丢弃后立刻再问同一密码。** 仅保存而不连接且未选择记住时，不持久化秘密，并清楚说明下次连接需输入。
- 短期密码不进入 HostConfiguration、SQLite、Codable、日志、argv、环境变量或普通临时文件。用绑定主机／请求／代次的一次性内存句柄，取消、关闭和失效后释放。
- 原数据库四种认证值要有兼容与迁移方案：普通密码和密码MFA均映射到“密码”展示，普通密钥和密钥MFA映射到“SSH密钥”展示，同时升级为新的按服务器挑战处理策略。保留主机ID、密钥／凭据引用及用户明确的保存授权，不能清库重建或把两个旧MFA值直接丢弃。

### 5.1 修复“改配置但仍打开旧连接”的误导

当前 `SessionController.open(.reuse)` 按主机ID复用活动标签。用户已真实遇到：密钥连接未关，编辑同一主机改为密码后点打开，实际回到密钥连接，误以为密码已登录。

- 为会话保留实际连接参数快照，与最新配置区分。
- 配置未变时可复用同一活动会话。
- 地址／端口／用户名／认证方式／密钥或凭据授权等连接相关参数变更后，点击连接应使用新配置建立新会话，不能悄悄把旧连接当新认证成功。保留旧会话供用户自行关闭，不擅自杀运行中的任务。
- 仅名称、收藏、分组、最近连接时间等展示元数据变化，不应触发无意义的重连或配置告警。
- 同理审查 `FilesController.show` 的整行相等比较：目前任何字段改变都可能触发 `files.hostChanged`。最近连接时间等元数据刷新不应被误报为连接参数变化；真正变更的连接仍保持原快照和明确的重新连接路径。
- 此处是需审查与复现的代码风险，不声称已确证图一的告警一定由时间字段造成。

## 6. 两类配置下自动响应 MFA 挑战

### 用户可见行为

用户只选密码或密钥，不预先选“有验证码／无验证码”。服务器无需MFA时正常完成；服务器实际要求附加验证时，自动展示属于当前会话的认证输入界面。支持多轮验证码、私钥口令、需要用户在手机上审批的等待、取消，以及SFTP的独立认证。

### 必须正视的现有技术边界

- 现有 SSH `.passwordOnly` 明确关闭 Keyboard-Interactive；普通私钥也仅在旧MFA选项下开启它。SFTP 的额外交互方法目前同样由旧MFA枚举决定。**只把四个选项改成两个，不是完成功能。**
- 系统 OpenSSH 普通 Askpass 请求不提供可靠的“这是登录密码／OTP／私钥口令”阶段类型。服务器的 challenge 文案也不构成可自动投递长期秘密的可信证明。
- “自动识别需要MFA”应实现为响应真实认证协议／受控回调里的挑战和部分成功状态，不是连接前保证判定OTP种类，也不是扫描终端文字看到password/error/OTP就猜测。
- 能获得可靠类型时显示清楚的标签；信息不足时显示“服务器要求进一步验证”及经安全显示处理的服务器提示，让用户作答，不把未知挑战谎称为验证码。
- 已保存或本次输入的长期密码只能在已证明属于相应初始密码认证的上下文使用；不能因为启用了KI，就把现有strict-password自动投递白名单扩到任意首个masked提示。OTP不保存，不对模糊KI提示自动填长期密码，不以提示词或请求顺序推断密码。
- 不允许先故意登录失败来“探测MFA”，也不允许用两次不同SSH连接假装同一条密码→MFA流程。重复错误和认证尝试应有界，取消立即生效。
- 若现有后端无法同时满足上述交互与上下文要求，U0阶段必须用实测明确差距，并实施有可靠阶段信息的成熟认证／传输方案；允许依既有授权记录ADR后调整核心实现。不自行写SSH协议，不修改系统ssh，也不以隐藏第二次密码提示或关闭校验掩盖问题。
- 内层ssh/sudo仍由远端终端手动处理，不捕获其文字向其自动投递App凭据。
- 同时两会话的挑战有明确主机／标签归属，取消A不能回答B；多提示、零输入通知、审批等待保持正确，不限定“一个框、一个数字”。

## 7. 首次连接提示按图二简化

- 首次未知服务器自动在当前连接流程显示一个简洁确认界面，包含主机、算法、完整可复制SHA256指纹；无需先点击“核实主机身份”，无需“我已通过独立渠道核实”的额外声明按钮。
- 三个操作清楚区分：**关闭**、**仅此次继续**（对应Continue）、**添加并继续**（对应Add and continue）。推荐将“添加并继续”作为清楚的主操作，绝不把仅此次继续偷偷解释为永久保存。
- “添加并继续”：持久保存本次明确选择的主机密钥，后续同端点、同受信密钥不重复询问，SSH/SFTP共享已有持久信任策略。
- “仅此次继续”：仅当前连接授权，不修改持久库，断开后授权结束，因此以后独立新连接仍可能提示。这一点用一句短说明表达；这是按钮语义差别，不是要求用户额外完成配置。
- 现有信任API若只支持持久确认，需新增真正的会话级授权及临时严格绑定方案，不能按钮写“仅此次”但实际落库。临时快照仅包含当前端点和本次明确接受的公钥，归属于当前会话／代次，结束清理；不制造第二套持久信任真源。
- 主机密钥变化仍阻止连接并显示新旧指纹及明确管理入口；不能静默覆盖，也不能把已知变化混成新主机的普通Continue。
- 不使用 `StrictHostKeyChecking=no`、忽略SFTP hostkey回调等方式实现少弹窗；“继续”后真实握手仍必须匹配本次接受的密钥。
- 多种主机密钥算法优先协商已信任的算法，避免同一连接连续弹三个确认；确认一个算法不等于信任所有未经确认的扫描结果。SSH/SFTP不能因都指向同地址便跳过实际握手校验。

- 保留主题／字体／字号和已有显式自定义颜色，迁移区分旧默认值与用户主动选择，避免覆盖用户设置。
- 保留 SwiftTerm 标准VT/ANSI渲染：16色、256色、真彩色、SGR重置、粗体、反显和光标控制。编译器输出了红色错误序列，终端就显示红色；**普通 `echo error` 或写入stderr本身不意味着红色，不按关键词强行上色。**
- 保留UTF-8、中文、Emoji、组合字符、IME组合输入、复制粘贴、Bracketed Paste、选择、历史滚动、搜索、Ctrl-C/D、方向键、Tab和常见快捷键。
- 验证实际实体键盘及粘贴。此前CUA的typeText出现过标点未保留而原生粘贴正确，不能用自动输入工具的差异直接判定或排除产品键盘问题。
- 真实调整窗口后Vim/tmux/htop布局应跟随变化，切回标签保留原视图及状态。保持有界历史和输出队列，不以删控制序列或截断UTF-8换取显示正常。
- 大段实现说明、白名单、原始字节、file-based Keychain、取消内部资源细节和错误代码移入详情／帮助。连接失败用用户能理解的阶段和可行动作呈现，不把握手、信任、密码错误全部叫同一种“认证失败”；无证据时不猜原因。默认不收集秘密或完整会话日志。

## 9. SFTP 固定工作页

- SFTP是独立全页，不再以右侧面板挤占Vault或终端。
- 参考图五：左侧本地、右侧远程，分隔条可拖；本地默认主目录或用户选择的位置，仅按需浏览元数据，不自动读取敏感文件内容。测试用独立临时目录，不扫描用户真实目录做测试数据。
- 右侧未连接显示“选择主机”，从Vault已有配置选择并连接，不重新填写一套主机／凭据。已保存凭据按已有授权使用，必要时由服务器触发认证／MFA。
- 两栏有面包屑／可编辑路径、上级、刷新、隐藏文件切换、文件名／大小／修改时间／类型等清楚列项；长名称保留底层精确字节，显示简化不能改变操作路径。
- 支持本地→远端上传、远端→本地下载、必要的跨栏拖放和Finder拖入；复用已验传输引擎。新建目录、重命名、删除、冲突、取消和传输进度有正常入口，不埋在大量常驻调试按钮中。
- 传输任务用SFTP页内可展开队列或可达任务视图，切到SSH/Vault不取消传输。关闭一个SSH标签不关闭SFTP；退出应用仍处理活动传输。
- 选另一主机时明确保留／关闭当前连接和任务，不能让旧认证回答发到新端点；当前SFTP路径不与终端中的cd自动绑定。端点／认证变更与纯展示元数据刷新分开处理。
- 保留覆盖前风险、原文件保全、流式传输、取消、临时残留和特殊文件名／符号链接策略；不要为像某个界面删掉必要的数据保护。低频技术能力检查可收进高级操作，不影响普通上传下载。
- 本轮要求本地↔直连远程两栏，不因此增加远程↔远程、经跳板SFTP、自动ProxyJump或端口转发。

## 10. 建议实施里程碑

每轮派工有Objective/Context/Scope/Acceptance/Verification/Return Contract。主管每轮读取实际diff和关键输出，独立复核重要行为，适用检查通过后自动继续。

| 阶段 | 具体交付 | 主管验收重点 |
| --- | --- | --- |
| U0 调查与接口验证 | 核对官方桌面资料及六图，逐页/控件/状态补齐覆盖矩阵，确定视觉token和资源所有权；调查布局/认证/迁移，验证MFA及仅此次信任最小探针 | 所有入口有归属，未知与设计选择有标记；不先做漂亮假页面，明确必须修改的后端 |
| U1 顶部工作区 | 固定Vault/SFTP、真实SSH标签、路由和生命周期接线 | 不是把旧四栏套进Tab；切页不重建，关闭范围正确 |
| U2 Vault与编辑器 | 整洁主机/密钥管理，弹性详情面板，本次密码连接，旧数据兼容 | 最小窗口可用、不丢数据，改变认证后不假复用旧会话 |
| U3 终端 | 全页黑底、ANSI、搜索、键盘/IME、尺寸与TUI | 实际终端，不是TextView模拟或仅改背景；颜色不按词猜 |
| U4 SFTP | 本地/远端双栏、主机选择、导航及真实传输 | 不占终端页，切页不停任务，路径和操作语义正确 |
| U5 连接体验与回归 | 两类认证/MFA、简洁首次确认、一次/持久信任、新旧配置行为 | 正负例、取消、并发、真实握手与资源；不能只改枚举文案 |
| U6 本地体验交付 | 收口完整规格及逐项矩阵，新版可运行构建、全页面和状态截图、操作说明、差异表、剩余人工项 | 不止检查主页面；必做项有代码/行为证据，用户体验候选就绪，停止Apple上传/最终出包，等待用户确认体验 |

U0通过不意味着要等用户重新批准已明确需求；工程细节自行判断。重大产品范围变化或确实缺少用户条件时集中提出，不重复询问已有决定。
