# 六张参考图：桌面体验文字视觉规格

日期：2026-10-30；2026-11-01适配Codex Desktop。本文来自Codex实际查看六张原图后的转写。当前执行端有图像能力时可直接查看原图及新版截图；文字规格仍作为布局/交互依据，不必重复派工转写，也不预设当前模型看不到图片。

**证据边界：** 本文中的“图中可见”是对静态截图的观察，“实现要求”是根据用户要求和完整体验规格作出的设计选择。截图不能证明点击、悬停、键盘、保存、认证或后台生命周期行为；这些仍需实际实现与验证。原图能看清某些私有地址、账户、路径和指纹，本文统一使用示例，不复制真实数据进代码或测试。

结合使用：`desktop-experience-spec.md`、`termius-redesign-handoff.md`、`termius-parity-matrix.csv`。本文补足视觉依据，不缩小116条体验要求。看不了图不再妨碍按文字设计实施，但不能据此把新App的视觉验收标为通过。

## 0. 先理解整体外观

用户要的是一个**标签驱动的工作区**，而不是传统“左边主机树，中间上方主机信息、中间下方小终端、最右常驻文件面板”的拼接窗口。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ● ● ●  [保险箱] [SFTP] [测试主机 ×] [另一会话 ×]  ＋                  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│              只显示当前标签的完整工作页                               │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

- 顶部标签栏贯穿整个窗口，macOS红黄绿按钮位于左侧。尽量与原生标题区融合，避免出现“普通标题栏＋厚工具栏＋第二条标签栏”三层堆叠；不以破坏窗口拖动/全屏行为实现融合。
- 保险箱和SFTP在所有页始终存在，顺序固定，不可关闭；只有后续会话可关闭。加号紧跟会话标签，右侧留弹性空白。
- 用户图里的管理页标签栏为深蓝灰色，下方为浅灰白管理区；终端页整体变成黑/炭灰色，上下连续。不是把终端本身放进一个白色大卡片。
- 管理页主要用整齐的平面分区、细线、适度圆角和少量强调色；没有大量大号原生胶囊按钮，也没有持续占屏的长篇安全/实现说明。
- 用户图比例随显示缩放而不同。以下pt尺寸和颜色是OpenLXSSH的实施起点，**是估计与设计建议，不是从截图精确采样的Termius官方参数**。以实际原生渲染调整，保持1000×650等已规定尺寸可用。

### 0.1 建议统一视觉值

| 元素 | 实施起点 | 注意 |
| --- | --- | --- |
| 管理页顶部栏 | 背景约`#2D344E`，高44～52pt | 文字/图标浅色，活动标签对比更明显 |
| 活动/悬停标签 | 活动约`#424B66`，悬停略提亮；圆角约8～12pt | 不靠颜色单独表达当前页和连接状态 |
| 管理主内容 | 约`#EDF2F4` | 不做纯白巨大空白面板套面板 |
| 侧栏/检查器 | 约`#F6F8F9`，边界细线约`#D7E0E5` | 与主内容有轻微层次，不做厚黑分隔 |
| 正文/次要文字 | 深蓝灰约`#202638`，次要约`#8797A3` | 次要文字仍要能阅读，禁用文字区别于正常次要信息 |
| 强调色 | 蓝色约`#2C93F5` | 选中轮廓、焦点和主要动作一致 |

## 1. 图一：当前OpenLXSSH的错误布局，仅作反例

文件：`01-current-overflow.png`，截图是旧App，不是目标Termius。

图中可见：

1. 最左侧侧栏已有内容被截断；中央上方同时摆主机表与很宽的主机详情；右侧仍有巨大的SFTP面板。
2. 主机表地址列被切掉。主机详情又占一列，旁边还有独立滚动条。
3. 终端被塞在中央下半部，只有部分高度，上方有自己的小会话标签、连接按钮、复制粘贴和常驻搜索条。
4. 终端前还有一大段关于外层连接、sudo、MFA、白名单的说明，继续挤占终端。
5. SFTP路径输入和右侧操作被窗口边缘裁切，下面又堆着上传/下载、创建、重命名、删除、能力探针与技术告警。
6. 根布局宽于实际窗口，左右都无法完整访问；出现几个竖滚动条不代表已解决横向挤占。

实现要求：通过真正的页面切换移除同时出现的主机/终端/SFTP多重列，不是增加总宽度、降低字号或只给旧面板外面套ScrollView。所有低频技术解释移到详情/帮助。

## 2. 图二：首次连接的简洁确认卡

文件：`02-first-connection.png`。这是接近正方形的连接状态卡截图，不要求App照搬其物理尺寸。

### 2.1 图中从上到下的层级

- 顶部左边一个圆角方形服务器图标，右边两行：较深的主机名、较浅的`SSH example.invalid:22`。
- 顶部右边一个“Show logs”按钮，作用表现为查看连接详情入口；截图没有展开它，不能断言日志内容。
- 再下是一条横向三节点进度线：插头、指纹、终端。前半段蓝色，后半段灰色，表示走到主机身份确认阶段。
- 正文标题是“Are you sure you want to connect?”，大号加粗深色字。
- 正文短段落说明无法确认服务器真实性；下一块显示算法与完整SHA256指纹；末尾询问是否加入已知主机。
- 底部一行三个按钮：左边Close，中间Continue，右边Add and continue。前两个深灰紫，最后一个亮蓝色；没有额外勾选或“已通过独立渠道核实”按钮。

```text
┌───────────────────────────────────────────────────────┐
│ [服务器图标]  测试主机                      [查看详情] │
│               SSH example.invalid:22                 │
│   插头 ━━━━━━━━━ 指纹 ────────── 终端                 │
│                                                       │
│ 是否连接到此服务器？                                  │
│ 这是第一次连接此服务器。                              │
│ 算法：……                                             │
│ SHA256：完整、可复制、可换行的指纹                     │
│                                                       │
│ [关闭]       [仅此次继续]       [添加并继续]            │
└───────────────────────────────────────────────────────┘
```

### 2.2 对OpenLXSSH的明确要求

- 自动在当前连接流程出现，不先要求用户找到“核实主机身份…”按钮。
- 用一个约560～680pt、能随内容换行的原生sheet/连接卡承载；背景柔和，文本左对齐，分组间距一致；窄窗按钮可调整排列而保持三种语义。
- 去掉冗长重复警告和额外核实声明门槛，保留短说明与完整可复制指纹。
- “仅此次”与“添加”必须有真正不同的临时/持久授权；用户点一次就继续当前流程，不能再弹第二个等价确认。
- 进度节点由真实连接阶段驱动，没有可靠阶段时宁可显示简洁文字状态，不播放假的成功动画。
- 主机密钥变化采用单独阻止流程，不能照抄首次连接的Continue作为默认放行。

## 3. 图三：保险箱中的密钥与凭据页

文件：`03-vault-keychain.png`。

### 3.1 可见结构

- 顶部深蓝灰横条上有Vault、SFTP、一个主机会话和加号，Vault处于活动态。会话并未因用户查看保险箱而消失。
- 左侧导航约占窗口宽度14%，浅灰白底，从上到下是Hosts、Keychain、Port Forwarding、Snippets、Known Hosts、Logs；每行左图标右文本，图标和文字有稳定起始线。
- Keychain这一行以宽圆角浅灰底高亮；不是在文字前加一个圆点，也不是一组纵向巨大按钮。
- 右侧内容顶部是一条工具行：左侧KEY带下拉、CERTIFICATE、FIDO2；右侧是搜索、视图排列等紧凑图标。
- 下方是很大的浅灰内容区，无条目时没有空表格边框。中央偏下有钥匙圆角方形徽章，下一行“Add credentials”，下面一句较浅说明。
- 没有额外详情面板占据右半屏；没有底部占空间的“完成”按钮要求退出整个工作区。

### 3.2 OpenLXSSH如何适配

- 保留相同的“侧栏＋工具行＋内容/空状态”层级，侧栏选择样式统一；密钥列表有数据时替换空状态即可。
- 侧栏主入口用主机、密钥与凭据、已知主机；设置放正常入口。原范围外的转发、命令片段、全文Logs按差异表处理，不能为了六行看起来齐全摆空按钮。
- 工具行优先是“生成密钥/导入”及必要下拉、搜索、视图/排序；证书/FIDO2未实现就不画可点击入口。
- 空状态用一个适度图标、一行标题、一句解释和可行动作，不把密钥格式/ACL/Keychain事务写成半页说明。
- 内容区占据标签栏下面的全部高度；切回SSH才显示终端，底部不保留另一个迷你终端。

## 4. 图四：完整终端页

文件：`04-full-terminal.png`。

### 4.1 可见结构

- 整个窗口从顶部到终端均为黑/近黑色；顶部标签以更深或较亮炭灰圆角块区分活动状态。
- 左上仍有交通灯、Vault、SFTP；主机会话处于活动态，图中会话关闭符号位于标签左部，标签右部另有小连接相关图标；加号在后。右上有小工具图标。
- 标签栏下面立即开始终端正文，左/上只有少量内边距，没有主机列表、主机详情、SFTP栏，也没有额外的一整排复制/粘贴/搜索按钮。
- 正文等宽浅灰白，shell提示与输出自上往下自然排列；下面整片空黑区域仍是终端区域，没有带边框的文本卡片。
- 光标是明显的浅色实心块。图中普通`echo "error"`输出仍是浅色，没有因为出现error单词而变红。

### 4.2 实现要求

- 激活SSH时，主要内容高度全部给真实终端；搜索仅Cmd+F或菜单打开时出现紧凑条，关闭恢复面积和终端焦点。
- 连接中/断开/等待验证的状态使用轻量就地呈现或连接卡；正常连上后不永久占一大排状态说明。
- 复制/粘贴、连接信息、重连和字号从快捷键、右键或紧凑菜单访问，不把所有功能常驻画出来。
- 主题应用于实际NativeTerminalView前景/背景/光标/调色板，不能只给SwiftUI外层涂黑而原生终端仍是白色。
- 编译器发送的ANSI红色应真实显示；普通stderr或普通文字不由关键词上色。终端所有VT/TUI/IME/选择/粘贴要求仍按完整规格验证。
- 图里的右上通知/协作等符号只说明布局紧凑，不授权新增团队、通知服务或空的侧面板按钮。

## 5. 图五：独立SFTP双栏工作页

文件：`05-sftp-two-pane.png`。

### 5.1 未连接时的可见布局

- 顶部仍是统一标签栏，SFTP为活动标签，主机会话还在。
- 标签下面整个内容按近似1:1左右分为两栏，只有细分隔线，无Vault侧栏、无主机详情、无底部终端。
- 左栏标题行：蓝色小本地图标和Local，右端Filter、Actions下拉；下面单独一行是后退/前进、蓝色文件夹图标和面包屑。
- 面包屑再下面直接是文件表格：Name、Date Modified、Size、Kind。列名加粗，细竖线分列；名称列最宽。
- 文件表有很淡的交替行背景，蓝色文件夹图标；名称下一行较小灰字显示权限。第一项为`..`返回上级；文件夹大小显示缺省符号，类型显示folder。
- 右栏未连接时整片浅灰底；中央偏下是文件夹徽章、Connect to host、一句说明、Select host按钮。没有先弹一大张连接配置表，也没有旧文件面板的常驻技术说明。

```text
│ …                        │                           │

```

### 5.2 连接后的实施设计（截图未展示）

- 右栏连接后使用与左栏相同的信息层级：真实主机/端点、筛选/操作、导航路径、文件表；不能继续嵌一整块旧侧边面板。
- 本地一侧在右边没有连接时仍完整可用。当前代码仅把旧远端面板移到SFTP页，不满足本图。
- 双栏各自独立导航、选择、刷新和滚动；分隔条可拖，窄窗列可裁减/横滚，但不能裁掉目标路径和主要动作。
- 上传/下载通过跨栏拖放、上下文菜单或紧凑动作完成；传输队列放底部可展开抽屉。队列高可限制并滚动，不把浏览表挤成几行。
- 无法用图五推断Termius的冲突弹窗和全部队列状态；按完整规格实现明确的覆盖/跳过/改名/取消，证据标为本项目设计。

## 6. 图六：主机列表与右侧Host Details检查器

文件：`06-host-details.png`。

### 6.1 三个横向区域

- 侧栏约14%宽，结构同图三，Hosts高亮。
- 中间主机区约59%宽；最上是一条宽搜索/快速连接输入，右边含CONNECT按钮；下一行工具栏左侧New Host带下拉、Terminal、Serial，右侧视图/标签/排序等小图标。
- 工具栏下面有Hosts分区标题与卡片列表，卡片不是占满内容宽的一块巨大表单。
- 右侧检查器约27%宽，与中间用细竖线分开，标题Host Details、编辑/更多/收起图标在同一行；其下是独立可纵向滚动的表单。

### 6.2 主机卡片

- 横向圆角矩形，左边是醒目的服务器/系统图标，右边两行：主机名称或地址、较浅的协议/用户名。
- 活动卡片白底，亮蓝描边约2pt；没有选中时保持更轻的边界。图里只有一个卡片，下面的大量空白是正常列表剩余空间，不应拿来塞终端或技术说明。
- 以1440pt窗口为例，可从侧栏220pt、检查器360pt、中间弹性剩余宽开始设计；不把截图中的物理宽度等比例硬编码到所有窗口。

### 6.3 右侧表单从上往下

1. **Address卡片**：小分区标题；下一行左侧图标，右侧一个IP或主机名输入框。
2. **General卡片**：名称/Label输入；父分组选择；标签输入/选择；退格行为等可支持的高级配置。各字段同宽竖向排列，字段间距统一。
3. **SSH与Credentials卡片**：SSH on [22] port紧凑一行；细分隔线；凭据标题；用户名输入；密码掩码输入；添加密钥/证书/FIDO等入口。
4. 底部可见Connect按钮，草稿尚无有效地址时呈禁用态。

卡片之间有明显但不夸张的垂直空隙，卡片内留约16～20pt内边距，输入框边界细，焦点蓝色描边，文字左对齐；滚动条在检查器内部，不是让整个窗口跟着表单滚动。

### 6.4 OpenLXSSH的适配

- 本轮仍明确保存/保存并连接；不要看见图里某些字段就把未经验证的自动保存作为既有功能。
- 密码/SSH密钥两种主认证方式用紧凑分段或选择器，下面仅显示当前相关凭据字段；两种方式都能按实际挑战追加验证。不能保留四个“含MFA”选项再称已按图实现。
- 密钥选择复用Vault实体；不实现证书/FIDO2等就不把它们写成能点的凭据项。Terminal/Serial/快速命令等范围外入口同理明确记录差异。
- 宽窗检查器占固定合理宽度，中间列表弹性；窄窗可变成可收起覆盖检查器，不能再次把主机列表挤出窗口。覆盖时有明确关闭入口，焦点和鼠标不能穿透到背后。
- 表单保存、放弃、错误定位、本次密码交接、现有数据迁移按完整规格执行；美观不能代替真实状态处理。

## 7. 无图像能力时怎样推进与验收
