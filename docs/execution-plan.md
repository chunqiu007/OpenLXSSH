## 1. 启动条件与授权

用户已正式启动当前工作区的开发 Goal。本文件保留连续实施计划与授权边界，实际已完成任务、当前委派和未满足条件见 `ENGINEERING_STATE.md`；恢复会话不从头重复已完成工作。

- 目标是一个连续 Goal，覆盖技术验证至可安装 V1.0；下列阶段是工程验收门槛，不是每轮向用户索取“继续”的节点。
- 主要实现按范围交给可用执行子智能体，主会话负责独立审查、验证和阶段结论；不依赖固定代理名字。普通失败继续修复，通过后继续下一项，不整批生成未验证的后续阶段代码。
- 可以自主选择普通工程细节、核对和下载必要开发依赖，并在满足需求、安全、许可证的前提下调整核心候选；核心变更记录 ADR 与复验，不重复请求已授予的技术调整权限。
- 可以初始化本地 Git；保留当前文档与用户改动，不向其他仓库目录初始化，不默认建立远程。主管在验收通过后按明确文件列表提交相关改动，不使用全量暂存混入凭据或无关文件。
- 先检查已有测试工具。新增 Linux 虚拟机/容器环境先提交具体方案、软件来源、资源与网络范围，获得用户确认后实施；不自动安装虚拟化工具或启用系统远程登录。
- 用户有开发者账号，但尚未确认具体证书与 Apple 上传授权。本地已有签名条件可检查并使用；登录、创建凭据、账号安全操作由用户完成。公证上传前展示将提交的具体构建产物、Apple 目的地与用途，集中确认一次；此时其他可执行工作应已完成。
- 不连接生产服务器。真实公司认证和第二台 Mac 验收由用户操作或在明确提供的授权测试条件下完成，不索要公司秘密。
- 文档只是执行上下文，不会自动导入所有相关文件。主会话应显式读取需求、架构、本计划、验收表与状态；派工中提供条目 ID 和必要背景。

## 4. 阶段 1：直接 SSH 认证与信任原型

原型置于清楚标识的测试/实验区域，可复用已验证部分；先证明基础链路，避免构建完整产品界面。

| Task ID | 执行任务 | 验收与证据 |
| --- | --- | --- |
| P1-01 | 最小 OpenSSH/PTY 进程启动、输入输出及关闭 | 无 Shell 拼接；可取消并回收进程与描述符 |
| P1-02 | App 独立配置与主机信任原型 | 首次确认、已知匹配、变化拒绝、非默认端口；不改系统配置 |
| P1-03 | Keychain 和私钥最小链路 | 有口令/无口令 Ed25519/RSA、保存授权和解锁失败行为；只用测试秘密 |
| P1-04 | Askpass 与 App 交互桥接 | 与 PTY 共存；会话归属、多会话隔离、取消与超时；无秘密进入参数或日志 |
| P1-05 | 验证四类认证和多轮挑战/审批等待 | 覆盖 AUTH-01～09；未知提示人工输入，不推测 OTP 类型，不无限重试 |
| P1-06 | 制作真实打包结构的最小认证探针 | 辅助程序在 `.app` 内可找到并运行；验证选定构建权限下的可行性 |

阶段通过：隔离服务上的直接认证可用、安全回退和资源释放有证据。模拟审批只证明交互状态机，不证明所有企业 MFA 厂商兼容；实际企业场景在最终人工验收记录。

## 12. 完成与等待规则

- CONTINUE：仍有可自行完成的任务，包含普通工程失败、构建失败和可修复环境问题，具体派工后继续。
- BLOCKED：缺少不可替代的信息、授权、测试环境或人工实测；先完成所有不受影响的必要工作，再报告具体缺口、证据和用户下一步。不反复发送相同问题，也不虚构Goal状态变更；遵守当前实际Goal工具的状态条件。
- COMPLETE：V1.0 必要功能、审查和验收全部通过，Release 可安装，必要人工验收有记录。单个阶段 DONE、本机 build 成功或候选安装包生成均不足以证明整体完成。
- 若已产出候选安装包而还缺公证或第二台 Mac 实测，汇报“候选版本已产出，待指定验收”，整体目标仍未完成。用户明确调整验收范围时先记录变更再重新判断。
- 尊重用户暂停与系统用量上限，不另开任务绕过；恢复时核对状态和实际代码，不从头重做。

## 13. 报告与文件约定

- `ENGINEERING_STATE.md`：当前目标、阶段、任务、证据摘要与下一项工作。
- `docs/acceptance.md`：验收总表及状态；保持需求编号可追踪。
- `docs/adr/`：产生实际架构决策时记录，含自主核心替换的证据。
- `docs/reports/`：阶段验收报告，含修改范围、检查、提交与待办。
- 测试日志与 Instruments 产物放入合适的本地目录，按需忽略大文件和敏感内容；报告引用路径与摘要，不能把真实终端秘密提交 Git。
- 每阶段简洁报告实现、验证与结论，通过后自动继续；用户不需要逐轮回复“继续”。
